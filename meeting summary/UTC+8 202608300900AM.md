# 技术会议总结

> [!info] 会议信息
> - **频道**：#程序猿

## 一、会议主题

1. Unity 版本统一
2. 项目上传和拉取测试、GitHub 个人分支创建
3. 共建提交规范（做到怎样才允许并入 main）
4. 任务划分协调（人力分摊到各部分，以及开赛后每人每时间段具体负责何事）

## 二、关键决议

### 1. 版本统一
- Unity 版本统一为 **Unity 6.5 (6000.5.9f1)**。

### 2. Git 协作与提交规范
- 个人分支创建测试，提交内容为：`this is test line from \[\[yourusername]]`。
- GitHub 下载/拉取测试：随便拉取一点东西即可，验证流程通畅。
- 并入 main 条件：每个人下载并 test，==正常运转才可并入 main==。

> [!tip] 提交提示
> 记得**校验哈希值**，确保传输无误。

### 3. 技术方案
- Prefab 构建等级：采用**泛用的可视化低代码或配置类快速构建方案**。
- 耦合控制：**预留 API 接口**，降低模块间耦合。

### 4. 交接规范

> [!important] 交接日志必写三项
> 1. **我完成了什么**（附 Git 提交号 / 资产路径）
> 2. **我卡在哪里**（需要谁、需要什么）
> 3. **你接下来该做什么**（明确的下一步指令）

对应 [[工程管线]] 交付物「交接日志模板」。
